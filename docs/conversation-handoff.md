## 同一终端内切换原生 /resume

切换当前对话不等于终端退出。原对话历史保留，后台任务是否结束不能仅从 /resume 推断；以原生写锁和任务状态为准。

启动记录仍显示“已准备”但原生写锁被占用时，界面说明原生会话已在使用、接管尚未确认，不自动取消。若确实未接管且原对话已空闲，可用“取消未接管启动”；迟到的旧 runner 会拒绝执行，原文件和修订保留。

对于本版本新启动的 Codex 任务，runner 会记录实际观察到的原生写锁接管。切换 /resume 后，选原对话并点击“同步已切出的原对话”：只有原生写锁已释放且存在接管记录时才同步和释放预约，终端仍为运行中，不伪造退出码或清理会话文件。旧任务缺少接管记录时保持保护；原生仍持锁时也不能释放。旧终端随后退出，若另一任务已接管同一逻辑对话，旧清理停止。

tests/verify_resume_switch.py 验证真实 Codex app-server 的写锁、空闲后同步、原文件保留和迟到清理保护，零模型请求；不等于已验证交互式 TUI 的选择器、后台任务和所有 CLI 版本。


## 使用方式

选中一条对话，选择 `codex1`、`codex2`、`claude` 或对应类型的自定义启动配置，点击“打开终端并继续”。选择入口只更新预览，点击继续后才创建新的临时原生会话，不需要手工创建并查找副本；同连接恢复仍使用所选原生 ID。旧目标已删除也直接创建新 ID，旧删除记录不变。Codex 已续聊副本也可再次跨 Codex 连接迁移，使用所选副本本身的内容。

默认使用单主会话：同一条逻辑对话只允许一个受管理的 Agent 启动任务。启动准备阶段即登记占用，独立终端进程执行前再次检查；重复点击、其他窗口或其他配置不能同时启动这条对话。切换前先退出当前 Agent 并等待同步。其他逻辑对话可以同时使用。

正常退出后，将刚续聊的目标文件直接提升为最新主会话；不再额外复制回原平台。统一数据库登记完整逻辑修订，验证原生内容后，清理被该主会话完整接替的旧转录、原生线程及列表缓存。下一次在相同连接继续使用该 ID；切换到其他平台／连接时创建新目标。正常完成后只保留一个可续聊原生转录文件，切换过程中允许源和目标暂时共存，文件名和原生 ID 可以变化。

右栏历史版本仍可查看；有多个独立分支时，启动入口会提示先合并分支。旧窗口直接运行 CLI、手工导入或外部程序仍可能产生并行内容；本工具不会覆盖或自动丢弃它们。通过 UI／启动配置准备接口创建的任务受独占约束，绕过这些入口直接执行旧 `codex2 -From ...` 命令不受此约束。

升级前已创建的任务沿用旧的返回／回收策略，避免改变正在运行任务的清理约定。关闭旧终端、完成待办、重新打开 UI 后，新启动默认采用单主会话。已有并行历史需先显式合并；已验证合并关系中的旧文件，在随后一次成功接续时也会按精确事件签名清理。

## 基线、版本与原生准备

`conversation_store.py` 使用统一数据库中的 `conversations`、`conversation_versions`、`conversation_revisions`、`handoff_publications`、`handoff_intents` 保存逻辑归组、物理身份、父修订、导入基线、发布与恢复信息。`temporary_handoffs.policy` 区分新单主会话和已有旧任务；`single_conversation.py` 用 `conversation_runs` 登记逻辑占用、`conversation_retirements` 持久化逐文件清理日志。

不可变修订快照位于数据目录的 `handoffs/revisions/`；每份保存原生记录、解析事件和接续事件映射。投影文件位于 `handoffs/projections/`。这些包含私密对话，不进入源码仓库；当前原生文件位于对应 Agent 目录。“一个文件”指正常完成后只剩一个可续聊转录；数据库、修订备份、转换投影、附件和原生运行缓存仍独立存在。

物理身份包含平台、连接／home、原生 ID 和规范文件路径。同 ID 的不同文件独立保留，不按标题／工作目录推断为同一条对话。首次接续登记完整基线，随后仅把基线之后的新事件纳入逻辑分支；相同问题再次发送仍是独立事件。

返回原平台时，沿接续关系寻找该平台最近的原生快照，保留原始上下文，再追加中间平台新增的可迁移文字／工具摘要。不会把整段带有导入提示的有损副本反复转换覆盖原始记录。同平台迁移继续使用 Codex 原生快照适配和 writer lock。

初次跨 Agent 转换沿用既有边界：Codex → Claude 默认约 20 万字符及近几轮工具摘要；Claude → Codex 保留文字和截断工具摘要。图片、附件、隐藏推理、工具执行状态无法完整迁移；历史工具不作为待执行命令重放。原生快照保留原始记录，逻辑事件／转换投影不等于完整运行状态。

## 同步与异常处理

- 终端启动前登记基线和独占任务；独立 `launch_job_runner.py` 在命令结束后依次采集、验证最新文件、提升主会话、清理已接替的旧文件，再释放占用。关闭 UI 不影响终端及正常结束后的收尾。
- 打开 UI、刷新历史、重试同步和下次启动时重新检查已登记版本；现有定时采集入口也会采集。没有安装定时任务也能在下次切换时获得内容。
- 半条 JSONL 不提交为消息；快照前后检查来源变化。压缩、截断、重写或 Claude UUID 更新保留为修订，不将全量副本盲目追加到父版本。基线不兼容时保留独立重写分支，不拼接不兼容的原生锚点。
- 跨平台启动使用新 ID；删除记录和已删除文件不复活。自动清理仅作用于同一逻辑对话中，能证明已被当前主会话完整覆盖的版本；新旧 Agent 内容通过精确事件前缀或已验证合并签名比较。独立手工导入和无接续关系的会话不清理。
- 正常结束后检查完整 JSONL 和写锁／运行进程，再验证修订事件及原生内容。Codex 额外通过实际 `thread/resume` 和分页回合读取检查文字，不发送模型回合。未通过检查不回收源文件。
- 外部窗口同时新增内容、原生分支仍引用源文件、来源被停用、校验失败时保留相关文件并记录待处理原因。新模式要求先显式合并并行历史；旧任务继续支持“保留分支并完成同步”。异常退出／中断须确认终端已关闭，再点“重试同步／刷新续聊”。
- 旧文件先进入 `handoffs/cleanup/任务ID/`，完成原生线程、缓存及统一库清理后再移除隔离文件。清理日志先于移动落库，中断后重试同一目标，不额外创建返回副本；原生 SQL 失败时恢复源位置。数据库修订备份、旧身份和删除记录保留；Claude 附件／子代理侧目录保留。
- 发布意图持久化，已发布但尚未登记的目标在下次采集时恢复关联。各原生数据库、转录文件及统一库不是跨库原子事务；发布前失败可重试，原生发布自身继续沿用适配器的备份／回滚规则。
- 终端报告进程异常消失时标记中断；下次刷新重新采集已保存内容。强制结束整个终端可能无法执行退出回调，因此不承诺强杀后立即同步。

旧导入映射可唯一定位来源时会归组；缺少历史导入基线的旧副本保留各自内容，作为独立分支，不猜测其增量。多文件来源有歧义时保持分开。新接续会建立准确基线。

## 显式合并多版本／多分支

`python conversation_merge.py` 刷新相关版本的快照并显示合并预览；加 `--apply` 执行，`--conversation 逻辑ID` 可限制范围。应用前备份完整统一数据库至数据目录 `merges/backup-时间/`；原始转录、原生 ID 和不可变快照保留，缺失／已删除版本不自动恢复。此入口目前要求 Codex 主版本，不调用模型，也不改变当前终端的会话。

当最完整版本已经包含其他版本的历史时，直接以该版本作为当前版本；有独立分支时，在当前连接创建新的可恢复合并会话。公共事件按身份去重；缺少准确旧基线的副本仅对完全相同的公共前缀去重，分叉后重复提问仍保留。分支顺序由主版本及明确的历史分支标记表达，不将并行历史伪装成逐条交错的时间线。

新合并会话是独立文字历史：保留可解析的用户／助手内容、工具全文和压缩摘要说明，历史工具作为文本，不重放工具或旧压缩／回退状态。附件、图片、隐藏推理、原生运行状态保留在原文件及快照，不宣称完整迁移。相邻助手内容合为同一条文本，避免原生投影仅展示最后一段。发布后核对全部文字及工具全文，并实际原生 resume／分页读回；失败时旧分支仍可见，未验证副本仅保留在发布日志中等待重试。

统一库 `conversation_merges` 记录源／目标的精确事件签名。默认列表与版本选择只列合并后的当前版本；开启“导入副本”仍能查阅物理记录。旧文件继续产生新消息，或合并文件被删除／重写时，相关旧版本自动恢复可见。备份、发布中间文件和报告都包含私人历史，位于源码仓库之外。更新后重开 UI 加载新逻辑。

正在使用的旧终端不会自动切换到新 ID。合并按已保存的快照截止；发布后只追加的来源允许完成快照归并，之后的新内容在采集时作为独立续聊恢复可见。要在统一历史上继续，请在 UI 选择合并版，或使用该连接的命令恢复新 ID。

## 启动诊断

最新目标成为主会话，旧原生 ID 会在成功清理后从原平台恢复列表移除。统一索引采集与验证／清理结果分别记录；清理失败时主文件和修订备份仍保留，任务占用等待重试。最新目标被用户删除时停止收尾；旧源文件被用户删除时不复活它。

“测试启动（不调用模型）”只检查工作目录、配置、程序和适配参数，不启动 Agent、导入副本或发送模型请求。实际启动才准备原生会话。

`launch-jobs/` 保存准备、运行、结束、失败／中断、退出码和同步状态，不保存环境变量值、完整参数或正文。右栏显示最新任务结果，“启动记录”查看最近记录；“重试启动”和“重试同步／刷新续聊”分别处理命令与采集失败。终端已打开、退出码为零都不能证明登录或原生恢复成功，恢复结果仍以终端为准。
