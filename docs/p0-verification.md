## 本次运行结果

从仓库根目录运行，均通过：

```shell
python -m unittest discover -s tests -t . -q
# Ran 109 tests — OK（本机 Tk 与 pythonw 场景执行，未跳过）
python tests/verify_handoff.py
python tests/verify_ui_resume.py
python tests/verify_claude_to_codex.py
```

三项原生脚本均使用临时目录和合成转录。Codex 原生接口验证列出、恢复、历史读取和重启；转换脚本还验证 writer lock、回收站和删除来源后仍可恢复。启动参数由真实 PowerShell／捕获程序单独验证，独立报告进程在没有 UI 的子进程中执行并采集结果。没有调用真实模型，不读取真实私密会话作为测试数据。

本轮异常回归修复：首次快照读取失败不隐藏原物理会话，后续采集可恢复；文件内容回退创建新的修订并保留旧快照，避免修订循环；逻辑对话中的其他版本读取失败时阻止默认接续，避免忽略其新增内容；采集锁未取得时报告可重试失败。

## 明确边界

- 用户确认的“同步回原对话”为逻辑归组与切换时携带最新分支。返回平台可产生新原生 ID；原文件／原 ID 自动回写不在本次范围。
- 验证原生恢复通过 Codex app-server 的 `thread/resume`，终端参数和生命周期另行验证；没有执行收费模型回合或交互式 Claude CLI 恢复。终端打开和退出码 0 都不作为登录／恢复成功的证明。
- 跨 Agent 转换保留可迁移文字和工具摘要，图片、附件、隐藏推理、执行状态及压缩边界无法完整迁移。历史工具不会作为待执行调用重放。
- 旧副本没有准确导入基线时保留独立分支；同 ID 多文件来源不明确时不自动归组。并行分支由用户选择，不按修改时间覆盖。
- 私密修订快照存于仓库外数据目录，当前没有独立保留期／垃圾回收入口。强制结束整个终端后，下次刷新补采集已落盘内容。
- Linux、发行安装包和完整开源发布仍按 P1／OSS 项跟踪，本次 P0 完成不表示这些项目已完成。
